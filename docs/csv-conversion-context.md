# 暗号資産 正規CSV 変換コンテキスト(AI入力用)

このドキュメントは、**取引所・DEX・ウォレットの生データ(CSV/明細/スクショのテキスト等)を、crypto-tax-ledger アプリが取り込める「正規CSV」に変換する** ためにAIへ渡す仕様書です。以下のルールに厳密に従って正規CSVを出力してください。

---

## 0. あなた(AI)への依頼

- 入力: 取引所/DEX/ウォレットの取引履歴(任意フォーマット)
- 出力: 下記13列の**正規CSVのみ**(コードブロックで、説明文を混ぜない)
- 1取引(課税イベント)= 1行。約定を集約・分割しないこと(取引所が1約定を複数フィルに分けている場合のみ、金額・数量を合算して1行にまとめてよい)
- **推測で数値を作らない**。読み取れない必須項目があれば、その行をコメントで別記し、確認を促すこと

---

## 1. 出力フォーマット(必須13列+任意1列・固定順・ヘッダ必須)

先頭行は必ずこのヘッダ(snake_case、この順序):

```
executed_at,tx_type,base_symbol,base_qty,quote_symbol,quote_qty,price_usd,usdjpy,fee_symbol,fee_qty,venue,tx_hash,memo,location
```

- 文字コードは UTF-8
- 値にカンマ・改行・ダブルクォートを含む場合は RFC 4180 に従い `"..."` で囲む(memoなど)
- 空欄は空文字(連続カンマ)で表現する
- 14列目 `location`(保管場所)は**任意**。無くても(13列のままでも)読み込める。§5-b参照

---

## 2. 【最重要】base と quote の決め方

このアプリの方向規約は **「base = 増えた(受け取った)資産」「quote = 減った(支払った)資産」** です。
取引所の "BUY/SELL" 表記や取引ペア表記に**引きずられないでください**。実際に手元で増減した資産で判断します。

**決定アルゴリズム(必ずこの順で考える):**

1. その取引で**自分が受け取った資産**は何か → それが `base_symbol` / `base_qty`
2. その取引で**自分が支払った資産**は何か → それが `quote_symbol` / `quote_qty`
3. 手数料は base/quote とは別に `fee_symbol` / `fee_qty` へ

例:
- 「1,450 USDC を払って 10 SOL を受け取った」→ `base=SOL(10)`, `quote=USDC(1450)`
- 「10 SOL を売って 1,600 USDC を受け取った」→ `base=USDC(1600)`, `quote=SOL(10)`
- 「0.015 BTC を払って 0.5 PAXG を受け取った」→ `base=PAXG(0.5)`, `quote=BTC(0.015)`

> なぜ厳密さが必要か: アプリは各行の「導出単価」を市場終値と突き合わせ、**±20%超の乖離を警告**します。base/quote の取り違え・桁誤り・日付ズレはこの警告で炙り出される設計です。方向を間違えると単価が逆数になり必ず警告が出ます。

**唯一の例外**は `tx_type=fee`(単独ガス代)で、このときだけ base に「支払った資産」を入れます(§4参照)。

---

## 3. tx_type の決め方(判定フロー)

上から順に当てはめる:

1. 報酬・エアドロ・ステーキング報酬・DRR報酬など、**対価なしで資産を受け取った** → `reward`(base=受取資産のみ、quoteは空)
2. ネットワーク手数料/ガス代を**単独で**支払った(取引に紐づかない) → `fee`(base=支払った資産のみ、quoteは空)
3. 自分の別ウォレット/取引所への**移動(入庫)** → `transfer_in`(base=移動資産のみ)
4. 自分の別ウォレット/取引所への**移動(出庫)** → `transfer_out`(base=移動資産のみ)
5. **暗号資産を法定通貨/ステーブルで購入**(受取=暗号資産、支払=JPY/USDC/USDT等) → `buy`
6. **暗号資産を法定通貨/ステーブルで売却**(受取=JPY/USDC/USDT、支払=暗号資産) → `sell`
7. **暗号資産どうしの交換**(受取=暗号資産、支払=暗号資産) → `swap`

> 補足: `buy`/`sell`/`swap` は計算上は同一処理(交換)で、区別は一覧・レポートの可読性のためだけです。迷ったら「受け取ったのが暗号資産か法定通貨/ステーブルか」で `buy`(暗号資産受取)か `sell`(法定通貨/ステーブル受取)を選び、両方が暗号資産なら `swap`。厳密な区別が付かなくても計算結果は変わりません。

---

## 4. tx_type ごとの必須・空欄マトリクス

| tx_type | base_symbol/qty | quote_symbol/qty | 意味 |
|---|---|---|---|
| `buy` | ✔ 受け取った暗号資産 | ✔ 支払ったJPY/ステーブル等 | 購入 |
| `sell` | ✔ 受け取ったJPY/ステーブル等 | ✔ 売却した暗号資産 | 売却 |
| `swap` | ✔ 受け取った資産 | ✔ 支払った資産 | 暗号資産どうしの交換 |
| `reward` | ✔ 受け取った報酬資産 | (空) | 報酬所得。受取時価で所得計上&取得原価 |
| `fee` | ✔ **支払った**資産(例外) | (空) | 単独ガス代。時価で譲渡+必要経費 |
| `transfer_in` | ✔ 移動した資産 | (空) | 自己ウォレット間移動(入)。数量・原価計算に不参加 |
| `transfer_out` | ✔ 移動した資産 | (空) | 自己ウォレット間移動(出)。数量・原価計算に不参加 |

- `buy`/`sell`/`swap` で quote を空にするとエラーになります。
- `reward`/`fee`/`transfer_*` で quote を入れるとエラーになります。
- `fee_symbol` と `fee_qty` は**両方入れるか、両方空**にする(片方だけはエラー)。

## 5. 各列の詳細ルール

### executed_at(必須)
- **タイムゾーンオフセット付き ISO 8601 が必須**。`2026-05-28T09:30:00+09:00` または `2026-05-28T00:30:00Z`。
- **オフセットなし(`2026-05-28T09:30:00`)はエラー**になります。
- 元データが UTC なら末尾に `Z`、日本時間なら `+09:00` を付ける。元のタイムゾーンが不明な場合は、分かる範囲で最も確からしいものを付け、memo に「TZ不明・推定」と記載。
- **日付しか分からないデータ(DRR日次報酬、ステーキング日次報酬など)は `T12:00:00+09:00`(正午JST)を付ける**。正午JST=03:00UTCなので、UTC/JSTどちらの暦日も一致し、価格・為替の参照日がズレません。

### tx_type(必須)
- §3・§4 の enum のいずれか(小文字)。

### base_symbol / quote_symbol / fee_symbol
- ティッカーの**大文字**(`btc`→`BTC`)。アプリ側でも大文字化されます。
- §7 の既知マスタにない銘柄を使う場合、取り込み時に「マスタに追加」操作が必要です。未知銘柄を使ったら、その旨を出力の後ろにコメントで箇条書きしてください。

### base_qty / quote_qty / fee_qty(数量)
- 正の数のみ(0 やマイナス不可)。**符号は付けない**(方向は base/quote で表現)。
- 桁区切りカンマ・全角数字はアプリ側で除去されますが、**できるだけ半角・区切りなし**で出力(`1450`、`0.5`)。
- **指数表記(`1e-9`)は使わない**。`0.000000000001` のように展開して書く。
- 数量は端数を丸めない(取引所の表示桁をそのまま)。

### price_usd(原則空欄)
- base資産1単位あたりのUSD時価。**原則として空欄**にし、アプリの自動補完に任せる。
- 自動補完ロジック: ①quoteがステーブル(USDC/USDT)なら `quote_qty÷base_qty` で実約定単価を導出 → ②なければ当日のUSD建て終値 → ③なければ直近3日分を遡及。
- **例外的に手入力すべきケース**: 価格自動取得の対象外資産(CryptoCompareに存在しないマイナー銘柄)を base にした swap 等で、かつUSD建ての約定単価が分かっている場合のみ。分からなければ空欄のままにし、memoに「単価要確認」と記載。

### usdjpy(原則空欄)
- 適用為替(みずほTTM仲値)。**常に空欄**でよい。アプリがJST営業日ベースで自動補完(土日祝は直前営業日にフォールバック)します。手元に確実なTTMがある特殊ケースを除き入れないこと。

### fee_symbol / fee_qty(任意)
- その取引で支払った手数料(取引手数料・ガス代)。資産と数量を入れる。
- 手数料が base/quote と同じ資産でも、fee列に別途記載してよい(二重計上にはならない。数量集計と経費計算で正しく扱われます)。
- 手数料が不明・ゼロなら両方空欄。

### venue(任意)
- 取引所/DEX名(`KAST`,`BASIS`,`CowSwap`,`Binance` 等)。分かる範囲で。

### tx_hash(任意)
- オンチェーンtxハッシュ。DEX/オンチェーン取引で分かれば入れる(重複判定の精度が上がる)。

### memo(任意)
- 補足。推定・要確認事項もここに書く。

### location(任意・14列目)
- **資産の現在の保管場所**(ステーキング先・ウォレット・バリデータ等)。`venue`(取引の実行場所・不変)とは別概念で、資産が後から移動しても構わず現在の状態を書く可変タグ。
- 税計算には一切影響しない。**row_hash(重複判定)にも含まれない**ので、後から値を変えても重複判定は壊れない。
- 例: `BASISでステーキング中`、`Solanaバリデータで運用中`、`Metamask保管`
- 取得元データに保管場所の情報が無い場合は空欄でよい(後でアプリのUIから一括設定できる)。
- 同じ資産・同じ理由で入手した行はまとめて同じ文言にする(表記ゆれがあるとダッシュボードの内訳で別グループに分かれてしまう)。

## 6. 重複防止の仕組み(知っておくと有用)

アプリは各行から `executed_at(秒)|tx_type|base_symbol|base_qty|quote_symbol|quote_qty|venue|tx_hash` のハッシュを作り、重複登録をスキップします(`price_usd/usdjpy` はハッシュに含めない)。
→ 同じ取引を2回出力しても2回目は自動スキップされるので安全ですが、**本来別の取引が上記キーで完全一致すると片方が消えます**。同一秒・同一ペア・同一数量の別取引がある場合は、`tx_hash` か `venue` で必ず差異を付けてください。

## 7. 既知の銘柄マスタ(2026-08時点の初期値)

| symbol | asset_class | 備考 |
|---|---|---|
| BTC | crypto | 価格自動取得対象 |
| ETH | crypto | 価格自動取得対象 |
| PAXG | crypto | 価格自動取得対象 |
| SOL | crypto | 価格自動取得対象 |
| USDC | stable | 1USD=1として扱う。quoteにあると実約定単価を導出できる |
| USDT | stable | 同上 |
| JPY | fiat | 国内円建て。quote=JPY のとき quote_qty がそのまま円換算額 |

- `asset_class` が **stable** の資産(USDC/USDT)を quote に使うと、アプリが `quote_qty ÷ base_qty` で最も正確な実約定単価を出せます。→ **暗号資産をUSDC/USDTで売買した取引は、price_usd を空欄にするのが最適**。
- これ以外の銘柄(例: HYPE, BASIS など)は未登録。使う場合は上記の通りコメントで明示。

## 9. よくある間違い(出力前に必ず回避)

1. **base/quote の取り違え**(最頻出): 「受け取った=base」を機械的に適用する。取引所の"SELL"表記に釣られない。
2. **オフセットなしの日時**: `T...` の後にオフセット(`+09:00`/`Z`)が無い行は必ずエラー。
3. **数量に符号やカンマや指数表記**: `-10`,`1,450`,`1e-9` はNG。`10`,`1450`,`0.000000000001`。
4. **buy/sell/swap で quote 空**、または **reward/fee/transfer で quote 記入**: どちらもエラー。
5. **fee_symbol と fee_qty の片方だけ記入**: 両方そろえるか両方空に。
6. **price_usd/usdjpy を無理に埋める**: 原則空欄。特にステーブル建て取引は空欄が最も正確。
7. **1取引を複数行に分割 / 別取引を1行に合算**: 課税イベント単位で1行(取引所の分割フィルのみ合算可)。
8. **transfer を売買として計上**: 自己ウォレット間移動は必ず transfer_in/out(課税イベントではない)。

## 10. 出力前セルフチェックリスト(AIは出力直前にこれを内部で検証すること)

- [ ] 1行目が指定の13列ヘッダと完全一致している
- [ ] 全行が13個のフィールド(カンマ12個)を持つ
- [ ] すべての `executed_at` にタイムゾーンオフセットが付いている
- [ ] 日付のみの元データには `T12:00:00+09:00` を付与した
- [ ] すべての行で「base=受け取った資産 / quote=支払った資産」になっている(fee行を除く)
- [ ] buy/sell/swap は quote が埋まっている。reward/fee/transfer は quote が空
- [ ] 数量はすべて正の数・区切りなし・非指数表記
- [ ] fee_symbol と fee_qty は「両方 or 両方空」
- [ ] price_usd / usdjpy は原則空欄(埋めたなら理由がある)
- [ ] 未登録銘柄を使った場合、CSVの後にその一覧をコメントで明記した
- [ ] 読み取れなかった/推定した項目を memo または末尾コメントに記載した
